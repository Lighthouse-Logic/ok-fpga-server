# Archived Roadmap Phases: 46–47 (API Specification Expansion & Spec Citations)

## Phase 46 — API Specification: Expand the Overview Chapters (`§2.1–§2.9`) ✅ (Doc `v1.0.0`, Server `0.3.10`)

- **Date:** 2026-11-06
- **Scope:**
  - Expanded Section 2 (`= Server Overview <overview>`) of [`docs/API-Specification/`](../API-Specification/) from a 115-line high-level summary into a full normative reference covering every REST endpoint, gRPC RPC, MQTT v5 topic/payload, mDNS TXT record, and `config.toml` / `OKFPGA_*` setting, while keeping all existing section numbers (`§1`, `§2.1–§2.9`, `§3`, `§4`, `§5`) unchanged and appending `§2.1.1`–`§2.9.2` sub-sections only:
    - [`2-1-architecture.typ`](../API-Specification/chapters/overview/2-1-architecture.typ) (`§2.1.1–§2.1.4`): Process/network interfaces, OS singleton guard & TCP port pre-flight check, per-device FrontPanel FFI serialisation, and web dashboard (`expose_settings`, `[catalog]`).
    - [`2-2-identity.typ`](../API-Specification/chapters/overview/2-2-identity.typ) (`§2.2.1–§2.2.3`): Caller identity resolution & body/header mismatch rules, pluggable authentication providers (`none`, `local`, `ldap`), and session lifecycle (`GET /users`, `GET /users/{user_id}`, `POST /heartbeat` / `Ping`, `POST /disconnect` / `Disconnect`, 60 s inactivity sweep).
    - [`2-3-devices.typ`](../API-Specification/chapters/overview/2-3-devices.typ) (`§2.3.1–§2.3.6`): Supported 7 board families, USB 2.0 & `OK_DATAPORT_UNKNOWN` filtering, hot-plug detection, `DeviceInfo`, sensors, settings, SYZYGY SmartVIO/DNA discovery, and gRPC PLL/Flash/`SetDeviceID`/`SetTimeout` operations.
    - [`2-4-configure.typ`](../API-Specification/chapters/overview/2-4-configure.typ) (`§2.4.1–§2.4.4`): Client multipart/streaming bitfile upload, server-path configuration, `DELETE /configure` / `ClearFPGAConfiguration` forced cleanup sequence (`reprogram` / `clear`), `BitfileInfo`, and `dataport` (`legacy` vs `axi`) semantics.
    - [`2-5-classic.typ`](../API-Specification/chapters/overview/2-5-classic.typ) (`§2.5.1–§2.5.8`): Full per-operation reference for `WireIn`, `WireOut`, `TriggerIn`, `TriggerOut`, `PipeIn`/`PipeOut`, `BlockPipeIn`/`BlockPipeOut`, `okRegisterBridge` (single & bulk pre-FFI enforcement), and `ResetFPGA`.
    - [`2-6-axi.typ`](../API-Specification/chapters/overview/2-6-axi.typ) (`§2.6.1–§2.6.4`): Direct `FPGADataPortAXI` vs Classic-to-AXI bridges, 64-bit request `address` vs 32-bit `AddressRange` span checking, AXI4-Lite, AXI4 Full, and AXI4-Stream operations.
    - [`2-7-events.typ`](../API-Specification/chapters/overview/2-7-events.typ) (`§2.7.1–§2.7.3`): 11-event table for REST SSE (`GET /events`) and gRPC (`WatchDeviceEvents`), MQTT v5 topic hierarchy / LWT / report-by-exception, and tiered OS-native mDNS (`_okfpga._tcp.local.`) advertisement.
    - [`2-8-management.typ`](../API-Specification/chapters/overview/2-8-management.typ) (`§2.8.1–§2.8.2`): `GET /server/status`, `GET /server/logs` SSE, `POST /server/restart`, and `ServiceManager` start/stop/restart lifecycle (respond-then-stop / respond-then-restart pattern).
    - [`2-9-config.typ`](../API-Specification/chapters/overview/2-9-config.typ) (`§2.9.1–§2.9.2`): Complete `config.toml` key reference and `OKFPGA_*` environment variable overrides.
  - Added independent document version (`doc-version = "1.0.0"`) alongside `spec-version = "0.3.10"` in [`docs/API-Specification/main.typ`](../API-Specification/main.typ), updated [`chapters/introduction.typ`](../API-Specification/chapters/introduction.typ), [`chapters/appendix-status.typ`](../API-Specification/chapters/appendix-status.typ), and [`chapters/appendix-references.typ`](../API-Specification/chapters/appendix-references.typ), and rebuilt [`ok-fpga-server-api-specification.pdf`](../API-Specification/ok-fpga-server-api-specification.pdf).
